# Structure Arrow Consequence v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the smallest executable falsifier showing that reciprocal structure, temporal arrow, and delayed consequence carry distinct information, then freeze the learned object and test whether it executes the held-out route task.

**Architecture:** A tiny forked-corridor world generates local transitions and delayed outcomes. `S` is learned as symmetric transition support, `A` as antisymmetric transition flux, `E` as decaying symmetric route eligibility, and `C` as symmetric consequence-weighted persistence. A frozen executor masks actions by `S`, uses `A` for forward direction, and `C` for which route is valuable; matched ablations isolate the three roles.

**Tech Stack:** Python 3.11+, NumPy, standard library `dataclasses`/`json`/`hashlib`, pytest for tests.

**Spec:** `docs/superpowers/specs/2026-09-28-structure-arrow-consequence-design.md`

## Global Constraints

- Python + NumPy only in product code unless a dependency earns its place.
- CPU-only; deterministic seeds; no expensive hyperparameter search.
- No tuning each ablation independently.
- No plotting is required for gate validity.
- Freeze one committed V0 configuration before interpreting the final receipt.
- Tests must pin algebraic invariants and causal boundaries, not only smoke behavior.
- Failed gates remain in the repository and are documented honestly.
- The README must distinguish older earned results, this repo's new result, and speculation.

## Review Focus

- **Repeated traversal scale:** normalization must prevent merely repeating one history more often from changing the sign semantics of `A`; Task 1 adds a scale-invariance/sign test.
- **Unseen/non-edge actions:** the executor must never traverse an edge absent from `S`; Task 4 adds an illegal-edge test.
- **Reward reassignment leakage:** reward identity must not alter `S` or `A`; Task 3 tests matrix equality before/after arm reassignment.
- **Shuffled consequence:** temporal reassignment of reward must destroy reliable route preference rather than accidentally preserve it; Task 3 tests a deterministic permutation control across 32 seeds.
- **Freeze integrity:** held-out execution must not mutate `S`, `A`, `C`, or configuration; Task 4 hashes matrices before/after all probes.

- [ ] **Step 2: Write the shuffled-consequence control**

- [ ] **Step 4: Implement balanced training and component scoring**
